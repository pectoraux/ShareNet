# PART A — Conformance Test Suite (Part 11)

## A1. Why this is the first deliverable, not the last

The audit's central finding is that the repository's M0 — described in its own roadmap as *"blocks everything"* — was never completed. The golden vectors are `sha256("cbor-manifest-0")` placeholders with all-zero signatures, the referenced Kotlin test resource does not exist, and there is no generator script. In its shadow, three genuine interoperability bugs survived undetected:

1. `TinkCryptoProvider` derives "public keys" as `sha256(handle.toString())`.
2. Kotlin and Python CBOR sort map keys differently.
3. Verification of any remote public key always returns `false`.

**Prose did not constrain the implementation. Executable vectors would have.** The conformance suite is therefore the precondition for letting any second agent touch the protocol, not a phase-3 nicety.

## A2. Structure

```
conformance/
├── vectors/                    # language-independent JSON, the ground truth
│   ├── 01-cbor.json
│   ├── 02-hashing.json
│   ├── 03-identity.json
│   ├── 04-chunking.json
│   ├── 05-merkle.json
│   ├── 06-manifest.json
│   ├── 07-receipts.json
│   ├── 08-frames.json
│   ├── 09-descriptors.json
│   ├── 10-routing.json
│   ├── 11-gateway.json
│   ├── 12-civic-points.json
│   ├── 13-revocation.json
│   └── 14-negative.json        # MUST-REJECT cases
├── generator/                  # ONE reference generator — Rust or Python
├── runners/                    # thin per-language harnesses
│   ├── kotlin/  python/  rust/  swift/  typescript/
└── SPEC-COVERAGE.md            # vector ↔ spec-section map
```

**Rule: exactly one generator.** Vectors are generated by the reference implementation and committed. Other implementations *consume* them and may never regenerate them. A generator per language reproduces the failure this suite exists to prevent.

## A3. Vector format

```json
{
  "suite": "cbor",
  "specSection": "SNP/0.1 §1",
  "vectors": [
    {
      "id": "cbor-map-ordering-length-first",
      "description": "RFC 8949 §4.2.1 — keys sorted by encoded bytes, length first",
      "input": { "id": "x", "capturedAt": 1710000000, "sourceLang": "tw" },
      "expected": { "cborHex": "a3626964617..." },
      "mustReject": false
    }
  ]
}
```

Every vector cites its spec section. `SPEC-COVERAGE.md` is checked in CI: **a normative MUST with no vector is a build failure.**

## A4. Required suites

| Suite | Must cover | Catches |
|---|---|---|
| **01 CBOR** | Length-first key ordering; shortest-form ints; byte vs text strings; nested arrays; null; ≥3 non-ASCII key cases; **rejection of non-canonical input** | The Kotlin/Python divergence |
| **02 Hashing** | SHA-256; HKDF; all `SIG_CONTEXT` domain separators | Cross-structure signature confusion |
| **03 Identity** | Ed25519 sign/verify with **raw 32-byte keys**; `NodeId` derivation; X25519; **verification by a key never seen before** | `TinkCryptoProvider`'s `sha256(toString())` and `createRawVerifyHandle` throwing |
| **04 Chunking** | Gear table values; boundaries for 0 B / 1 B / MIN−1 / MIN / TARGET / MAX / MAX+1; a 100 MB deterministic stream | Chunking drift = dedup fork |
| **05 Merkle** | RFC 6962 leaf/node prefixes; 1, 2, 3, 5, 8, 1000 leaves; proofs at every index; **empty**; **odd-count non-duplication** | CVE-2012-2459 pattern |
| **06 Manifest** | Canonical bytes; signature; `chunkCount` mismatch rejection; expiry | — |
| **07 Receipts** | Delivery, transit, gateway, custody; signature forgery rejection; **cross-type replay rejection** | Missing domain separation |
| **08 Frames** | Encode/decode; TTL decrement; TTL=0 drop; class discrimination; **padding buckets**; oversize rejection | — |
| **09 Descriptors** | Node descriptor; gateway advert; expiry; **capability/platform consistency** | iOS advertising `MESH_RELAY` |
| **10 Routing** | Metric arithmetic; path-vector loop detection; `seq` regression rejection; selection given a fixed topology; **migration on gateway loss** | — |
| **11 Gateway** | Mode A bundle; `tlsTermination` enforcement; **RFC 1918 egress rejection**; quota enforcement | SSRF pivot (T9) |
| **12 Civic Points** | Value function with fixed inputs; sub-linear volume; diversity collapse; holdback/clawback | Per-byte farming |
| **13 Revocation** | Propagation; monotonicity; **un-revoke rejection** | — |
| **14 Negative** | Every MUST-REJECT in the spec | Permissive parsers |

## A5. Suite 14 is the one that actually matters

Positive vectors prove an implementation can do the right thing. **Negative vectors prove it refuses to do the wrong thing** — and the audit's worst findings were all permissiveness:

```
FakeCryptoProvider.verify()  →  return signature.size == 64
```

Mandatory MUST-REJECT vectors:

| Case | Prevents |
|---|---|
| Signature valid length, wrong content | The above |
| Signature by the wrong key | Impersonation |
| Receipt signed by claimant not beneficiary | Point farming |
| CBOR with non-canonical key order | Signature ambiguity |
| CBOR with duplicate keys | Parser disagreement |
| CBOR with trailing bytes | Injection |
| Manifest whose `chunkCount` ≠ leaf count | Merkle ambiguity |
| Merkle root from duplicated odd node | CVE-2012-2459 |
| Frame with TTL 0 forwarded | Routing loops |
| Route advert containing own `NodeId` | Loops |
| Route advert with regressed `seq` | Poisoning |
| Expired descriptor used for routing | Stale routes |
| Gateway `CONNECT 192.168.1.1:80` | LAN pivot |
| Replayed circuit `seq` inside window | Replay |
| Un-revoke message | Revocation reversal |
| Mode A request without `tlsTermination` | Silent plaintext |

**An implementation that passes all positive suites and fails Suite 14 is non-conformant and MUST NOT be merged.**

## A6. Interop matrix

Vectors prove *encoding* agreement. They do not prove two implementations can *talk*. A live interop harness is also required:

```
                Kotlin  Python  Rust  Swift
    Kotlin        ✓       ·       ·      ·
    Python        ·       ✓       ·      ·
```

Each cell runs: handshake → descriptor exchange → Class A object transfer → circuit open → Class B transit → gateway migration. Run nightly, all ordered pairs.

## A7. Definition of conformant

An implementation is conformant when it (1) passes all positive suites, (2) passes Suite 14 entirely, (3) passes live interop against the reference in both directions, and (4) advertises only capabilities its platform sustains per the Platform Matrix.

**No document, README, or roadmap may describe a milestone as complete without a passing conformance run.** This rule exists because `README.md` currently states "M0-M5 implemented" against one test file in the entire Android codebase.

# PART B — Multi-Agent Development Model (Part 12)

## B1. The drift problem

Multiple AI agents implementing one protocol drift in a characteristic way: each makes locally reasonable decisions that are globally incompatible. The Kotlin/Python CBOR divergence is exactly this — both implementations are defensible, both are documented as "RFC-deterministic," and they produce different bytes.

Drift is not prevented by better prose. It is prevented by **executable constraints and explicit ownership.**

## B2. The four-tier constraint hierarchy

```
TIER 0  GOLDEN VECTORS          machine-checked. Disagreement = you are wrong.
TIER 1  NORMATIVE SPEC          MUST/SHALL. Change requires ADR + version bump.
TIER 2  API CONTRACTS           interface signatures. Change requires ADR.
TIER 3  IMPLEMENTATION          free choice. Language, structure, style.
```

**An agent may make any Tier 3 decision freely and may make no Tier 0–2 decision at all.**

Conflict resolution is mechanical: Tier 0 beats Tier 1 beats Tier 2 beats Tier 3. If an agent believes a vector is wrong, it files an ADR; it does not change the vector.

## B3. Invariants — violating any of these is a rejected PR

**Protocol**
- I1 — All signed structures use SNP-CBOR with length-first key ordering.
- I2 — Every signature is over `SIG_CONTEXT ‖ CBOR(payload)`.
- I3 — Ed25519 uses raw 32-byte public keys on the wire.
- I4 — `NodeId = SHA-256("SNP/0.1 node\0" ‖ pk)`, never the bare key.
- I5 — Merkle is RFC 6962; odd nodes are never duplicated.
- I6 — Chunking constants are frozen.
- I7 — Frame TTL ≤ 16, decremented every hop.

**Architecture**
- I8 — Class B payloads are never inspected, cached, or duplicated by relays.
- I9 — L8 (transport) never imports L6 (routing).
- I10 — L6 never imports a platform SDK.
- I11 — Platform-specific code exists only in L9 adapters and link implementations.
- I12 — No node advertises a capability its platform cannot sustain.

**Security**
- I13 — Civic Points are never minted by the claimant.
- I14 — Economic state is never eventually consistent.
- I15 — Revocation is monotone.
- I16 — Reputation is locally computed; never accepted as authoritative from a peer.
- I17 — Mode/`tlsTermination` downgrade is fail-closed, never automatic.
- I18 — Gateways reject RFC 1918 / loopback / link-local / multicast egress by default.
- I19 — No `Fake*` type is referenced from a `main` source set.
- I20 — A stub in a security-critical path throws; it never returns a permissive default.

## B4. Forbidden architectural changes

An implementation agent MUST NOT, under any circumstance, without a human-approved ADR:

1. Change any frozen constant (Protocol Spec §10).
2. Change CBOR key ordering, or "optimise" canonical encoding.
3. Merge Class A and Class B handling paths.
4. Introduce a "trusted" node role, super-peer, or privileged directory.
5. Make Civic Points transferable between users.
6. Make settlement eventually consistent, or points spendable while pending.
7. Let a relay decrypt, cache, or deduplicate transit traffic.
8. Add automatic mode downgrade or automatic `tlsTermination` relaxation.
9. Make hardware attestation a gate rather than an advisory reputation input.
10. Define protocol semantics in terms of a platform API (the `EndpointId`-is-a-Nearby-ID mistake).
11. Reward a contribution type that has no proof object.
12. Remove or weaken a negative conformance vector.
13. Reintroduce a permanent global public key as the primary identity.
14. Claim a platform capability without citing the specific API that provides it.

## B5. Module ownership

Exactly one agent owns each module. Others may read it, may file issues against it, and may not modify it.

| Module | Owner | Rationale |
|---|---|---|
| `spec/`, `conformance/` | **Human + Claude** | Tier 0/1 — the constraint source |
| `reference/` (Rust, Linux) | **Z.ai** | Reference implementation defines truth |
| `core-*` Kotlin | **Gemini/Android Studio** | Android port |
| `platform-android/` | **Gemini/Android Studio** | `VpnService`, links, FGS |
| `platform-linux/`, `platform-windows/` | **Z.ai** | TUN/WinTun |
| `platform-ios/` | **deferred** | Needs entitlements + human review |
| `backend/` | **Z.ai** | Settlement — 🔴 human review gate |
| `card-applet/` | **Human only** | 🔴 Hardware + key ceremony |
| Crypto primitive selection | **Human only** | 🔴 |
| Civic Point parameters | **Human only** | 🔴 Economic policy |

**Cross-module changes require the owning agent's PR.** An Android agent that needs a protocol change files an ADR; it does not edit the spec.

## B6. ADR process

```
docs/adr/NNNN-title.md
  Status: proposed | accepted | rejected | superseded
  Tier affected: 0 | 1 | 2
  Change · Rationale · Alternatives · Conformance impact
  · Migration path · Human reviewer (required for Tier 0/1)
```

Tier 0 and Tier 1 ADRs require **named human approval.** Tier 2 requires the owning agent plus one reviewer.

## B7. Per-task agent brief template

Every task given to an implementation agent must carry this header, so the constraints travel with the work:

```
TASK:            <what to build>
MODULE:          <owned module>
TIER:            3 (implementation)
SPEC SECTIONS:   <normative references>
VECTORS:         <suites that must pass>
INVARIANTS:      <applicable I-numbers>
FORBIDDEN:       <applicable B4 items>
REVIEW:          🟢 auto | 🟡 human security review | 🔴 human design required
DEFINITION OF DONE:
  □ Vectors pass       □ Interop passes      □ No Fake* in main
  □ No `// Real:` TODOs in 🟡/🔴 paths       □ ADR filed if Tier 0-2 touched
```

## B8. CI gates

1. Conformance vectors — all suites, including Suite 14.
2. Interop matrix against the reference.
3. **Grep gates** — build fails on `Fake` imported in a `main` source set; on `// Real:` or `// In production` in a 🟡/🔴 path; on `TODO` in a security path.
4. Spec coverage — every normative MUST has ≥1 vector.
5. Capability audit — advertised capabilities match the Platform Matrix.
6. Invariant lint — layering violations (L8→L6, L6→platform SDK).

Gates 3 and 5 exist specifically because the audited repository would fail both, and no existing check caught it.

## B9. Bootstrapping order — non-negotiable

```
1. Human + Claude   spec/ + conformance vectors + ADR process     ← WEEKS 1-3
2. Z.ai             reference impl (Rust/Linux), regenerates vectors
3. Z.ai             interop harness
4. Gemini           Kotlin core-* against vectors
5. Both             live interop Kotlin ↔ Rust
6. Parallel         platform adapters
```

**No implementation work begins before step 1 is complete.** This is the process lesson of the audit: the existing repository ran steps 4–6 without step 1, and produced 100 Kotlin files with one test, a broken crypto provider, placeholder vectors, and a README asserting compliance that no code had ever checked.
