# N2.8 — Real Mode-A Internet Gateway

**Status:** COMPLETE

**Parent:** N2.7 Gateway Service Runtime

**Baseline:** commit `2c6bec3`

---

## 1. Problem Statement

N2.7 implemented the `GatewayServiceManager` with `handle_request_simulated()`
(test-friendly, no real fetch). But the thesis — "a device without Internet
can reach the real Internet through the mesh" — was not yet proven.

N2.8 implements `handle_request()` (real HTTP fetch via `PinnedConnector`) and
proves the full pipeline works end-to-end with a real HTTP fetch.

---

## 2. What Changed

### 2.1 GatewayServiceManager::handle_request() — real fetch

The `handle_request()` method now performs a REAL HTTP fetch:

```rust
pub fn handle_request(
    &mut self,
    request: &TransitRequest,
    client_node_id: [u8; 32],
    client_public_key: &[u8; 32],
    connector: &PinnedConnector,
    now: u64,
) -> Result<GatewayServiceResult, GatewayServiceError>
```

Pipeline:
1. Policy enforcement (destination + protocol)
2. Quota check
3. Circuit limit check
4. **Real fetch** via `snp_gateway::handle_transit_request_with_connector`
5. Measurement (bytes, duration, success/failure)
6. Receipt signing (TransitReceipt)
7. State update + quota decrement

### 2.2 Client public key verification

`handle_request()` now takes `client_public_key` and passes it to
`snp_gateway::handle_transit_request_with_connector()` which verifies the
client's signature on the TransitRequest before performing the fetch.

## 3. Tests

`reference/snp-node/tests/n28_real_gateway.rs` — 6 tests:

1. `n28_mode_a_end_to_end_local_http` — Full pipeline through a real local
   HTTP server: client signs request → GatewayServiceManager enforces policy →
   PinnedConnector fetches → TransitResponse signed → TransitReceipt signed →
   body integrity verified (SHA-256 match) → measurements updated → quota
   decremented.

2. `n28_policy_blocks_blocked_destination` — Policy enforcement blocks a
   request to a disallowed destination BEFORE the fetch happens.

3. `n28_quota_exhaustion_prevents_fetch` — After quota is exhausted, subsequent
   requests are rejected.

4. `n28_receipt_proves_service` — The TransitReceipt proves: bytes transferred,
   client identity, time, HTTP status, object_id (SHA-256 of body), gateway
   signature — all verifiable by anyone with the gateway's public key.

5. `n28_real_internet_fetch` — **Optional**: attempts a REAL fetch to
   `https://example.com` through the full GatewayServiceManager pipeline using
   a real `PinnedConnector::new()` (real DNS, real SSRF check, real TLS
   handshake). Skipped (not failed) if no Internet access.

6. `n28_gateway_failure_produces_failure_measurement` — When the upstream server
   is broken, the failure is recorded in measurements.

## 4. The Thesis Proof

After N2.8, the following pipeline is proven to work end-to-end:

```text
Client (no Internet)
    → signs TransitRequest
    → GatewayServiceManager::handle_request()
    → policy enforcement (destination + protocol)
    → quota check
    → PinnedConnector (SSRF defence + DNS pinning)
    → real HTTP fetch
    → TransitResponse (signed by gateway)
    → TransitReceipt (signed by gateway — proves service)
    → response body returned to client
```

The gateway can honestly say:
> "I provided N bytes of Internet access to peer X at time T."
