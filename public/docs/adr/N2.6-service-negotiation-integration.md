# N2.6 — Integrate Service Negotiation into Routing

**Status:** COMPLETE

**Parent:** N2.5.1 Architecture Freeze

**Baseline:** commit `21d1c63`

---

## 1. Problem Statement

N2.5 introduced the service negotiation model (ServiceRequirement,
CapabilityOffer, PolicyConstraint, CapacityConstraint,
NegotiatedServiceAgreement) as a separate module. But it was NOT
integrated into the routing pipeline.

Before N2.6:
```
Topology → Route Discovery → Circuit
                              ↑
                    ServiceAgreement (typed but NOT negotiated — just a string)
```

After N2.6:
```
Topology
    ↓
Candidate Discovery
    ↓
Service Negotiation (requirement → offer → policy → capacity → agreement)
    ↓
Authenticated Route (RouteProposal WITH NegotiatedServiceAgreement)
    ↓
commit_route() enforces: gateway routes MUST have a valid negotiation
    ↓
Circuit
```

A route to an InternetGateway destination can no longer be committed merely
because the destination advertises Gateway — the requested service must be
permitted and supported.

## 2. What Changed

### 2.1 RouteProposal gains `negotiated_service` field

```rust
pub struct RouteProposal {
    // ... existing fields ...
    /// N2.6: The negotiated service agreement (required for InternetGateway
    /// destinations). `None` for non-gateway routes or legacy compatibility.
    pub negotiated_service: Option<NegotiatedServiceAgreement>,
}
```

### 2.2 New constructor: `from_validated_path_with_negotiation()`

```rust
pub fn from_validated_path_with_negotiation(
    path: &ValidatedPath,
    source_secret_key: &[u8; 32],
    source_public_key: &[u8; 32],
    service: ServiceAgreement,
    negotiated: NegotiatedServiceAgreement,
    expiry: u64,
) -> Result<Self, RouteSerializationError>
```

The existing `from_validated_path()` remains for backward compatibility,
but `commit_route()` will reject gateway routes built without negotiation.

### 2.3 New `negotiate_service()` function

The integration point between route discovery and service negotiation:

```rust
pub fn negotiate_service(
    requirement: ServiceRequirement,
    offer: CapabilityOffer,
    policy: PolicyConstraint,
    capacity: CapacityConstraint,
) -> Option<NegotiatedServiceAgreement>
```

Returns `None` if the requirement is not satisfied by the offer/policy/capacity.

### 2.4 `commit_route()` enforces negotiation

New step 4b in `commit_route()`:
```
4b. If the destination has RouteRole::Gateway:
    - proposal.negotiated_service MUST be Some(NegotiatedServiceAgreement)
    - else: CommitError::ServiceNegotiationRequired
    - if Some: re-verify the negotiation is still valid
    - else: CommitError::ServiceNegotiationInvalid
```

### 2.5 New CommitError variants

```rust
ServiceNegotiationRequired { destination: [u8; 32] },
ServiceNegotiationInvalid { destination: [u8; 32], reason: String },
```

## 3. The Pipeline

```
Client needs Internet transit
    ↓
ServiceRequirement {
    capability: InternetGateway,
    required_destinations: ["*:443"],
    required_protocols: ["https"],
    min_bandwidth_bps: Some(10_000_000),
    max_latency_ms: Some(500),
}
    ↓
Gateway advertises:
    CapabilityOffer { capabilities: [InternetGateway], service_types: ["internet-transit"] }
    PolicyConstraint { allowed_destinations: ["*:443"], allowed_protocols: ["https"] }
    CapacityConstraint { max_circuits: 100, available_bandwidth_bps: 50_000_000, ... }
    ↓
negotiate_service(requirement, offer, policy, capacity)
    ↓
NegotiatedServiceAgreement (matched + signed terms)
    ↓
RouteProposal::from_validated_path_with_negotiation(path, sk, pk, service, negotiated, expiry)
    ↓
commit_route(proposal, acceptances, &path, now)
    ↓
CommittedRoute (gateway route WITH valid service negotiation)
    ↓
Circuit establishment
```

## 4. Tests

`reference/snp-node/tests/n26_service_negotiation_integration.rs` — 7 tests:

1. `n26_gateway_route_without_negotiation_rejected` — gateway route without
   negotiation is rejected with `ServiceNegotiationRequired`
2. `n26_gateway_route_with_negotiation_commits` — gateway route with valid
   negotiation commits successfully
3. `n26_route_with_blocked_destination_negotiation_fails` — negotiation
   fails when policy blocks the required protocol; commit rejected
4. `n26_route_with_insufficient_bandwidth_negotiation_fails` — negotiation
   fails when capacity is insufficient
5. `n26_gateway_route_always_requires_negotiation` — any route to a Gateway
   destination requires negotiation, regardless of service type
6. `n26_has_negotiated_service_helper` — the `has_negotiated_service()`
   helper works correctly
7. `n26_full_negotiation_to_commit_pipeline` — end-to-end: requirement →
   offer → policy → capacity → negotiate → proposal → acceptances → commit

All existing routing tests (n212, n213, n214, n215, n25_conformance) were
updated to use `from_validated_path_with_negotiation()` for gateway routes.
