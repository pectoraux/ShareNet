# N3.4 — Content Re-integration

**Status:** COMPLETE

**Parent:** N3.3 Multi-Process Network Harness

**Baseline:** commit `19410e5`

---

## 1. Problem Statement

N3.3 proved the network works as a multi-process system. But the content
subsystem (chunking, Merkle, CAS, manifests) was not integrated — it existed
as a separate `snp-object` crate with `todo!()` implementations.

N3.4 integrates content with the proven network:
```
network (N3.3) → ContentService (N3.4) → CAS / Merkle / chunking
```

## 2. What Changed

### 2.1 ContentService

New module: `reference/snp-node/src/node/content_service.rs`

- **ContentChunk**: SHA-256-addressed data chunk with hash verification.
- **ContentManifest**: signed envelope binding publisher identity + chunk
  list + Merkle root. Uses RFC 6962-style leaf/intermediate prefixes.
- **ContentStore**: in-memory CAS (hash → chunk data) + manifest store.
- **ContentService**: publish (chunk + manifest + store), retrieve (fetch +
  reassemble + verify Merkle root), verify (manifest signature).

### 2.2 Content shares network identity

The publisher's Ed25519 keypair is the SAME keypair used for the network
layer (NodeAdvertisement, TransitRequest signatures). Content is NOT a
separate identity system.

### 2.3 Content is NOT arbitrary Internet transit

Content is mesh-understood, cached, content-addressed. It is NOT opaque
Class B transit traffic. The content service handles:
- Chunking (1 MiB chunks)
- Merkle root verification (RFC 6962)
- Manifest signing (publisher identity)
- CAS storage (content-addressed)

3. Merkle root verification
4. Large content (3 MiB → 3 chunks + round-trip)
