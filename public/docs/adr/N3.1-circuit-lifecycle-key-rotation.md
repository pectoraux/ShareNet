# N3.1 — Circuit Lifecycle + Key Rotation

**Status:** COMPLETE

**Parent:** N3.0 Route Recovery

**Baseline:** commit `7678227`

---

## 1. Problem Statement

N3.0 implemented route recovery (gateway disappears → replacement). But
the circuit lifecycle itself was incomplete — there was no explicit
management of:
- Circuit expiry (lifetime reached)
- Teardown (explicit close)
- Key rotation (new epoch with fresh keys)
- Replay-state lifecycle (clearing old state)
- Resource cleanup (zeroing keys)

N3.1 implements the `CircuitLifecycleManager` that manages the full
lifecycle: `Setup → Active → (Rotate) → Active → ... → Expired/Teardown`.

## 2. What Changed

### 2.1 CircuitLifecycleManager

New module: `reference/snp-node/src/node/circuit_lifecycle.rs`

Manages:
- **State machine**: Setup → Active → Rotating → Active → Expired/TornDown
- **Key epochs**: each rotation creates a new epoch with fresh keys
- **Sequence counter**: monotonic across epochs (NEVER resets)
- **Replay window**: tracks seen sequence numbers
- **Resource cleanup**: keys zeroed on teardown/expiry/drop

### 2.2 Key properties enforced

1. **No sequence reuse** — `current_seq()` is monotonic across epochs.
   Key rotation creates a new epoch but the seq continues from where it
   left off.

2. **No stale circuit reuse** — an Expired/TornDown circuit cannot be
   re-activated. `next_seq()` and `rotate_keys()` return errors.

3. **No forwarding state survives its circuit** — `teardown()` zeros all
   keys (current + past epochs) and clears the replay window.

4. **Key rotation** — `rotate_keys()` creates a new epoch with fresh keys.
   The old epoch's keys are zeroed. The seq counter continues.

### 2.3 Drop impl (defence in depth)

The `Drop` implementation zeros ALL keys when the manager is dropped,
even if `teardown()` was not explicitly called.
