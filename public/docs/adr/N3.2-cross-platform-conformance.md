# N3.2 — Cross-Platform Conformance

**Status:** COMPLETE

**Parent:** N3.1 Circuit Lifecycle + Key Rotation

**Baseline:** commit `d766b60`

---

## 1. Problem Statement

N2.5.1 created frozen conformance vectors as JSON files, but only for the
capability-authority suite. The other N2.5-N3.1 protocol objects (evidence
model, gateway service, contribution, circuit lifecycle, capability bridge)
had Rust unit tests but no serialized cross-platform vectors.

N3.2 makes ALL N2.x-N3.x protocol objects genuinely cross-platform by:
1. Generating frozen JSON vector files for every protocol object.
2. Creating a standalone runner that LOADS the files (not constructs objects).
3. Proving determinism (same inputs → same outputs, every time).

## 2. What Changed

### 2.1 New vector file: `17-cross-platform-n2x.json`

34 vectors across 5 suites:
- **evidence-model** (5): EvidenceLevel classifications (Authenticated, Observed,
  Reported, Derived, Inferred) — is_routing_evidence + is_untrusted + display.
- **gateway-service** (8): GatewayPolicy evidence levels + destination matching
  (wildcard, glob-suffix, exact-match) + capacity evidence level.
- **contribution** (2): ContributionProof verification + CivicPoint computation
  (1 MiB, 1 client → 20 points: 100 × log₂(2) × 0.2).
- **circuit-lifecycle** (7): State transitions (Setup→Active, Active→Expired,
  Active→TornDown, invalid transitions rejected).
- **capability-model** (13): NodeCapability → ProtocolCapability bridge
  mappings for all 13 variants.

### 2.2 Vector generator: `gen_n32_vectors.rs`

Generates vectors from deterministic inputs. Can be re-run to verify
determinism.

### 2.3 Cross-platform runner: `n32_cross_platform_conformance.rs`

9 tests that LOAD JSON vector files from disk and verify:
- Ed25519 signature verification (language-independent)
- SHA-256 hashing (language-independent)
- Capability string round-trip + typed checks
- Evidence level classifications
- Gateway policy destination matching
- Contribution proof verification
- Civic point computation (sub-linear + diversity)
- Circuit lifecycle state transitions
- Capability bridge mappings
- All vector files are JSON (language-independent)
- Determinism (re-deriving from same inputs produces identical outputs)

## 3. Cross-Platform Agreement Contract

```
Rust bytes = Kotlin bytes = Python bytes = Swift bytes

For every signed structure:
  load cbor_hex + signer_public_key_hex + signature_hex from JSON
  verify: ed25519_verify(signer_pk, preimage, signature) == true

For every hash:
  load cbor_hex + digest_hex from JSON
  verify: sha256(cbor_bytes) == expected_digest

For every string mapping:
  load string from JSON
  verify: parse(string) + serialize(parsed) == string

For every computation:
  load inputs from JSON
  verify: compute(inputs) == expected_output
```

A Kotlin/Python/Swift implementation that loads the SAME JSON files and
produces the SAME pass/fail results proves cross-platform agreement.
