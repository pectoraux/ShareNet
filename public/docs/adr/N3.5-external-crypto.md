# N3.5 — External Crypto Bridge

**Status:** COMPLETE

**Parent:** N3.4 Content Re-integration

**Baseline:** commit `c2d194e`

---

## 1. Problem Statement

N2.8 proved Internet gateway transit. But the audit's deferred feature —
external crypto operations through ShareNet — was not yet implemented:

```
Feature 1: RPC relay
ordinary wallet → ShareNet → gateway → blockchain RPC → response

Feature 2: Signed transaction broadcast
offline signed tx → ShareNet → gateway → broadcast → tx hash
```

N3.5 implements both features with two CRITICAL constraints:
1. **No private-key custody** — ShareNet NEVER holds private keys.
2. **No blockchain consensus** — ShareNet does NOT validate transactions.

## 2. What Changed

### 2.1 External Crypto Module

New module: `reference/snp-node/src/node/external_crypto.rs`

- **RpcRequest**: wallet-signed request for a blockchain RPC call (e.g.,
  `eth_getBalance`, `eth_call`). Contains method, params, endpoint, wallet
  signature. NO private keys.
- **RpcResponse**: gateway-signed response from the blockchain RPC endpoint.
  Verifiable by the wallet.
- **SignedTransactionBroadcast**: wallet-signed request to broadcast a
  pre-signed transaction. The `signed_tx_bytes` are OPAQUE to ShareNet —
  it doesn't parse or validate them. The `tx_hash` (SHA-256 of the bytes)
  is verified for integrity.
- **BroadcastResult**: gateway-signed result containing the blockchain's
  transaction hash.
- **ExternalCryptoGateway**: handles RPC + broadcast requests. Verifies
  wallet signatures, checks endpoint authorization, signs responses.

### 2.2 No private-key custody

The wallet signs transactions OFFLINE before sending through ShareNet.
The `SignedTransactionBroadcast` contains:
- `signed_tx_bytes` — opaque, already-signed bytes
- `tx_hash` — SHA-256 of the bytes (integrity check)
- `wallet_signature` — over the BROADCAST REQUEST (not over the tx itself)

ShareNet NEVER sees:
- The wallet's private key
- The transaction's unsigned form
- Any way to derive the private key

### 2.3 No blockchain consensus

The gateway's `handle_broadcast()` does NOT:
- Parse the `signed_tx_bytes` (they're opaque)
- Validate the transaction's correctness
- Check the transaction against blockchain state
- Run any consensus logic

It ONLY:
- Verifies the wallet's authorization (signature)
- Verifies the `tx_hash` (integrity)
- Submits the opaque bytes to the broadcast endpoint

## 3. Tests

10 tests in `n35_external_crypto.rs`:
1. RPC relay round-trip
2. Broadcast round-trip
3. **No private-key custody** (gateway never sees the key)
4. Invalid wallet signature rejected
5. tx_hash integrity verification (tamper detected)
6. Unauthorized endpoint rejected
7. Gateway signature verifies (and rejects wrong key)
8. Broadcast result signature verifies
9. **No blockchain consensus** (relays opaque bytes without understanding)
10. Full pipeline (RPC relay + broadcast)
