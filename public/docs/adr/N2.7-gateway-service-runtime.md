# N2.7 — Gateway Service Runtime

**Status:** COMPLETE

**Parent:** N2.6 Service Negotiation Integration

**Baseline:** commit `5391447`

---

## 1. Problem Statement

N2.5-T5 introduced the `GatewayServiceState` model (separating static identity
from dynamic service state). N2.6 integrated service negotiation into routing.
But there was no **runtime** that actually:

1. Accepted transit requests from clients via circuits
2. Enforced the negotiated policy (destinations, protocols)
3. Tracked quota (remaining bytes)
4. Measured actual service (bytes transferred, duration, success/failure)
5. Produced signed receipts proving the service was provided

N2.7 implements the `GatewayServiceManager` — the runtime that makes the
gateway a functioning service, not just a data model.

---

## 2. What Changed

### 2.1 GatewayServiceManager

New module: `reference/snp-node/src/node/gateway_service_manager.rs`

The manager wraps the existing `snp_gateway::handle_transit_request_with_connector`
with:

1. **Policy enforcement** — checks URL host + protocol against `GatewayPolicy`
2. **Quota tracking** — checks remaining quota before fetch, decrements after
3. **Measurement** — tracks bytes, duration, success/failure in `GatewayMeasurement`
4. **Receipt production** — signs a `TransitReceipt` for every served request
5. **State management** — maintains a `GatewayServiceState` with live measurements
6. **Circuit limit** — enforces max concurrent circuits

### 2.2 TransitReceipt

A new signed receipt type:

```rust
pub struct TransitReceipt {
    pub req_id: [u8; 16],           // replay defence
    pub client_node_id: [u8; 32],  // who received the service
    pub gateway_node_id: [u8; 32], // who provided the service
    pub bytes_transferred: u64,    // how much data
    pub http_status: u16,          // success indicator
    pub object_id: [u8; 32],       // SHA-256 of body (verifiable)
    pub served_at: u64,            // when
    pub duration_ms: u64,          // how long
    pub gateway_signature: [u8; 64], // gateway's Ed25519 attestation
}
```

Evidence level: `Authenticated` (signed by gateway).

The receipt is the gateway's honest attestation:
> "I provided N bytes of Internet access to peer X at time T for request R."

### 2.3 GatewayPolicy gains enforcement methods

Added `destination_allowed()` and `protocol_allowed()` to `GatewayPolicy`
(matching the same logic on `PolicyConstraint` in `service.rs`).

## 3. The Runtime Pipeline

```text
TransitRequest (from client via circuit)
    ↓
GatewayServiceManager::handle_request()
    ↓
┌─ 1. Policy enforcement (destination allowed? protocol allowed?)
├─ 2. Quota check (remaining >= expected bytes?)
├─ 3. Circuit limit check (active < max?)
├─ 4. Actual fetch (via snp_gateway)
├─ 5. Measurement (bytes, duration, success/failure)
├─ 6. Receipt signing (TransitReceipt)
└─ 7. State update (GatewayServiceState updated)
    ↓
GatewayServiceResult { TransitResponse, TransitReceipt, body }
```

## 6. Connection to N2.9 (Contribution Proof Loop)

The `TransitReceipt` is the foundation for the contribution proof loop:

```text
TransitReceipt (N2.7 — this milestone)
    ↓
ContributionProof (N2.9 — future)
    ↓
CivicPoints (N2.9 — future)
```

A gateway accumulates `TransitReceipt` records. These receipts are then
aggregated into `ContributionProof` objects that prove the gateway provided
real service to the network. The proofs are verified and credited as
Civic Points.
