# N2.9 — Contribution Proof Loop

**Status:** COMPLETE

**Parent:** N2.8 Real Mode-A Internet Gateway

**Baseline:** commit `fa0ddf0`

---

## 1. Problem Statement

N2.7 produced `TransitReceipt`s (signed proof that a gateway provided service).
N2.8 proved the real Internet gateway pipeline. But there was no connection
from receipts to Civic Points — the economic thesis was unproven.

N2.9 closes the loop:
```
TransitReceipt (N2.7)
    → ContributionProof (N2.9 — aggregate receipts)
    → CivicPointLedger (N2.9 — verify proofs → credit non-transferable points)
```

## 2. What Changed

### 2.1 ContributionProof

New module: `reference/snp-node/src/node/contribution.rs`

Aggregates one or more `TransitReceipt`s into a single signed proof. Each
receipt is individually verified before inclusion.

Anti-fraud: a node cannot manufacture a valid proof solely by asserting
traffic. Every receipt must:
- Be signed by the contributor (gateway's Ed25519 key)
- Have `gateway_node_id == contributor`
- Have a unique `req_id` (no duplicates within the proof)
- Not be in the future

### 2.2 CivicPointLedger

Credits non-transferable points from verified proofs:
- Verifies the proof signature AND every individual receipt signature
- Filters out already-credited receipts (replay defence via `(contributor, req_id)` set)
- Computes points: `base_rate × log₂(1 + MiB) × diversity_factor`
- Sub-linear in volume (per ADR-0005)
- Diversity-weighted (1 client → 0.2, 5+ clients → 1.0)

### 2.3 ContributionRecord

Audit trail: "Why did this node receive these points?" → traceable to
specific receipts → specific HTTP fetches → specific `object_id` (SHA-256
of response body).

## 3. Tests

10 tests in `n29_contribution_proof.rs`:
1. Build + verify ContributionProof
2. Ledger credits points from verified proof
3. Cannot manufacture contribution with fake receipts
4. Replay prevention (same receipt not credited twice)
5. Duplicate receipt within a proof rejected
6. Sub-linear volume factor (doubling volume does NOT double points)
7. Diversity weighting (more clients = more points)
8. Evidence level = Authenticated
9. Future timestamp rejected
10. Full loop: receipt → proof → points → trace

- ✅ A node cannot manufacture contribution solely by asserting traffic
- ✅ Points are sub-linear in volume
- ✅ Diversity weighting works
- ✅ Replay prevention works
- ✅ Full audit trail (points → proof → receipts → service)
